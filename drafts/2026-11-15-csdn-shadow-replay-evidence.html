LLM API 网关上线前怎么做影子流量回放？用 Python 生成可审计证据包

AI 客服、内容生成、数据分析和 SaaS 功能接入新的 LLM API 网关时，直接切生产流量验证会把网络、成本和业务副作用混在一起。更稳妥的上线前步骤是：对经过批准的脱敏 fixture 做确定性 shadow replay，再比较 baseline 与 candidate，并把结果归档为上线证据包。

ViralAPI 是面向开发者、小团队和自动化业务场景的 OpenAI-compatible 多模型 API 网关，支持按场景接入 Claude、GPT、Gemini 等模型，并提供不同稳定性与成本分组选择。价格应按预算、稳定性和业务场景选择：福利分组官方 1.5 折，官转分组官方 6 折，稳定官方分组官方 8 折。折扣价格不等于 SLA。

一、影子回放的边界

下面的示例纯离线运行，不捕获真实流量、不调用模型，也不代表生产性能或 SLA。生产采集应在边界处完成字段白名单、邮箱/token/银行卡号脱敏，并避免保存完整 prompt 和响应。

from shadow_replay_evidence import build_evidence_pack

fixtures = [{
    "request_id": "support-001",
    "model": "gpt-4o-mini",
    "prompt": "summarize a redacted support ticket",
    "authorization": "Bearer test-token",
}]

pack = build_evidence_pack(fixtures, candidate="viralapi-gateway-candidate")
print(pack["summary"])

二、baseline 与 candidate 怎么比较

证据包记录请求数、通过数、失败数、逐请求状态、模型、决策和稳定摘要。示例使用排序 JSON 计算 SHA-256 前缀，candidate 名称不参与比较 hash，因此相同输入在两次离线回放中可复现。这个 hash 不是模型响应 hash，也不能证明语义等价。

python -m unittest discover -s examples/python -p 'test_shadow_replay_evidence.py' -v

三、生产 gate 应额外记录什么

  • request_id、route、attempt、status_code、timeout_ms、decision、policy_version。
  • 429、5xx、超时、认证错误要分开统计，避免把网络故障误判为模型质量。
  • AI 客服、发券、邮件和计费等有副作用的请求，需要幂等键、人工复核和 kill switch。
  • 先 shadow，再按租户或业务场景灰度；批量摘要可优先考虑预算分组，实时客服更重视稳定性与观测。

四、适合和不适合谁

适合有真实调用量、能自助接入、有基础技术能力的小团队、开发者和同行渠道；不适合小白、白嫖、低预算试玩、高售后消耗或滥用客户。

FAQ

影子回放是否复制真实请求？

本文只处理人工提供的脱敏 fixture。真实复制前要经过隐私、合规和数据保留审批。

ViralAPI 价格组怎么选？

按预算、稳定性、并发和业务场景选择。福利分组官方 1.5 折、官转分组官方 6 折、稳定官方分组官方 8 折，价格优惠不等于 SLA。

回放失败先查什么？

先查 fixture 是否缺少 prompt、脱敏是否破坏结构、模型和路由白名单，再看超时、429、5xx、fallback 和 request_id。不要对未知副作用请求无限重试。
